# Leaf 04 — Connect dispatch, state and recovery

**Entry:** Leaves 01–03. **Output:** `succession/runner.py`, `succession/__main__.py` and `tests/test_runner.py`. Expose `run_once() -> Decision` on a runner that takes the controller, local state path, repo reader and desktop adapter. The command entry point `python -m succession` uses the same runner as the tests.

1. Test through the runner with injected observations and a fresh temporary state file. Assert that streaming, user/tool, duplicate and foreign events invoke neither the repo reader nor Send. Only an eligible completed `TASK_COMPLETE` reads the current remote state once. Test valid completion with work remaining, programme finish, exact cap, same-chat continuation at cap, worker `ERROR` and malformed status.
2. Serialize events and owner pause with the send boundary. Save the controller's decision before preparation. After destination/draft checks and payload readback, call `begin_send` and persist `sending`. A failed save or an effective pause prevents the click. Then call the adapter's one-click method. Confirm only positive, action-specific posted-message evidence and persist the result. Otherwise persist or retain the uncertain outcome. Keep observations distinct from the proposed action and only count the confirmed saved ID.
3. Wire `python -m succession start --config <config> --state <path>` and the equivalent `resume` command to the runner. The config contains the nomination and locally selected adapter bindings. Start initializes a fresh run from an observed saved initial worker. Resume loads and validates the existing state. Missing/corrupt state holds without creating a replacement count. Expose status, pause and reconciliation through the single-writer runner. On restart, inspect a persisted attempted Send read-only, adopt positive delivery once or explicitly rearm on positive no-submission evidence. If an owner pause remains active across reconciliation, keep dispatch paused until resume. Show current chat, repo/branch, last status, pending action, elapsed wait where available and reason.
4. Add fault tests for save failure before click, pause while prepared/after a click is in flight, interruption after typing but before saving `sending`, restart after saved `sending` before click, lost acknowledgement both for continuation and successor, lost state and duplicate acknowledgement. Assert send call counts and preserved draft/history, no count reset and no rearm from missing sidebar evidence. Test a full fake two-worker run with validated publication and terminal stop via the command's normal wiring. Record the no-Send help invocation.
