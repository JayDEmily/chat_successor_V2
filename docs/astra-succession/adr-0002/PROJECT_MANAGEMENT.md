## Goal

Pass a bounded GitHub job through fresh chats in a verified Project. Each worker follows a short repo and branch pointer, does the repository’s assigned work and publishes its result. One existing Windows controller per run verifies the current worker’s published receipt before it opens one successor or stops. Same-chat continuation preserves the worker count. The repository carries the assignment, progress and next action.

## How to work one leaf

- **Start at the first unresolved step.** For an uncertain Send, preserve the original intent, draft and run state. Inspect the saved chat read-only and reconcile that action only after the exact post and destination are verified. Never repeat a possibly submitted action to obtain evidence. If the current input or reply cannot be tied to the saved chat, record what is missing and hold.
- **Use the existing controller first.** When a diagnostic browser tool cannot select or verify the active tab, use the controller’s saved-view recovery for a known Project and saved chat ID. Verify the actual destination and composer through the existing checks. Resolve a one-time setup problem at that step and use the existing polling and waits.
- **Test the behavior the next run will use.** For a receipt-reader repair, inspect the existing attempt or a known first post in a saved disposable chat read-only. Also exercise the completed-chat and continuation paths affected by the change. Add a focused regression when existing coverage misses the defect. Carry forward evidence for unaffected paths. Run the full suites and independent review at the published gate, with GPT-6.2 Sol at high reasoning for independent code review. Judge useful work by the published commits, observed successor and terminal journal.
- **Keep the record short.** Record the leaf, tested revision, observed result, evidence and next action in `PROGRESS.md`. Use standing authorization for ordinary in-scope work. Pause for owner approval before adding a structural script, service, state-format change or broader reader design. Keep the worker pointer and receipt protocol stable for this qualification. Worker prompt cleanup (U02) follows stable end-to-end operation.
