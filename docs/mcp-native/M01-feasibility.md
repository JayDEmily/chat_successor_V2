22 November 2026 AEDT. Source checkpoint `366e2e7a2e34e7564198794027560649ac8fd9d5`. Disposition: discovery completed; transport pattern credible, native launch/identity not qualified. No new runtime or Send.

## Current official interfaces (read 22 November 2026)

- [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels): private outbound HTTPS, local forwarding, separate tunnel identity, ChatGPT private custom plugin via Tunnel. No inbound public MCP listener needed. Workspace access and runtime authentication are distinct from per-worker authorization.
- [Custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server) and [connect/test](https://developers.openai.com/plugins/deploy/connect-chatgpt): read and write MCP calls are supported; configure and test the actual connection. The supported documented creation path is ChatGPT plugin configuration, not a conversation creation API.
- [Plugin reference](https://developers.openai.com/plugins/reference): openai/session correlates calls within a conversation and openai/subject is an anonymized user identifier. Neither is documented as a saved-chat URL, Project identifier, owner approval, user-message attestation or finality. [MCP server guidance](https://developers.openai.com/plugins/build/mcp-server) and [authentication](https://developers.openai.com/plugins/build/auth) require server-side authorization; registration/completion mutate state and cannot be labelled read-only.
- [Desktop Chat/Work](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex) and [Windows app](https://help.openai.com/en/articles/9982051-using-the-chatgpt-windows-app) document user-driven new conversations and Project entry. No documented public consumer ChatGPT conversation launch/readback automation API was identified in these sources. Do not confuse Responses API agents, Spaces or Work sessions with saved consumer Project chats.
